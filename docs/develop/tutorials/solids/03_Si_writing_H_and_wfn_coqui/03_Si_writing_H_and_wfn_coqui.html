3. Writing a Hamiltonian File and a Trial Wavefunction Using CoQuí#

Goal: Become acquainted with how to write a Hamiltonian and a trial wavefunction to the SAFIRE HDF5 format.

3.1. What You Will Learn#

  1. How to write a Hamiltonian to the SAFIRE HDF5 format, using CoQuí, starting from a Quantum ESPRESSO calculation

  2. How to write a trial wavefunction to the SAFIRE HDF5 format, using CoQuí, starting from a Quantum ESPRESSO calculation

3.2. External Software#

In addition to SAFIRE and safiretools, we will be using the following software packages:

  • Quantum ESPRESSO (QE) for density functional theory (DFT) calculations, and some integrals via its post-processing utilities

  • CoQuí for generating the SAFIRE Hamiltonian and trial wavefunction HDF5 files from the output of QE.

  • pw2coqui.x see the instructions there for adding this to your QE build.

Note:

This tutorial assumes familiarity with Quantum ESPRESSO (QE); we will point out some specific settings that are necessary for the workflow, but a general tutorial on QE is beyond the scope of this tutorial.

3.4. Introduction#

In previous tutorials, we learned how to run SAFIRE, and how to post process the results to arrive at the AFQMC energy.

Now, we will learn how to write a Hamiltonian and a trial wavefunction in SAFIRE’s HDF5 format. CoQuí (Correlated Quantum ínterface) is a software project designed for ab initio electronic structure beyond density functional theory (DFT). It implements several many-body perturbation theory approaches and supports other methods such as dynamical mean-field theory and AFQMC. For SAFIRE, CoQuí can be used to directly generate second-quantized Hamiltonians and wavefunctions starting from a DFT calculation.

In this tutorial, we will generate the Hamiltonian and trial wavefunction for Si in the primitive cell.

3.5. Setup#

First, we need an orthonormal basis to express the second quantized Hamiltonian in. We will run Quantum ESPRESSO (QE) to generate a set of Kohn-Sham orbitals to use as a basis. We assume knowledge of the basic use of QE in this example, but we’ll point out a few details that are relevant to the workflow here. All input files are provided in files/qe.

Important:

You will need to install the pw2coqui.x converter in your QE build. See the above!

We will perform the following calculations with QE:

  1. self-consistent DFT with a large k-point grid, but a minimal number of bands

  2. a one-shot DFT calculation starting from the converged result in Step 1, but at the \(\Gamma\)-point and using a large number of bands.

  3. run the pw2coqui.x post-processing utility to generate data that we will need later.

Note:

CoQuí expects to find [prefix].coqui.h5 in the QE output directory. Double check that the output path of the post-processing tools are all set to the same directory.

Set QE_BIN to the directory holding pw.x and pw2coqui.x, and COQUI_EXEC to the CoQuí executable. All calculations run in a scratch directory data.

# create scratch directory in notebook path
%mkdir -p {_dh[0]}/data
%cd -q {_dh[0]}/data

3.5.1. Step 1: Self-Consistent DFT#

To generate the Hamiltonian for SAFIRE, we need to set force_symmorphic=.true. in the &system input card. Run self-consistent DFT with the provided input file and pseudopotential.

3.5.2. Step 2: One-Shot DFT#

The goal here is to generate the orbitals we need for the second quantized Hamiltonian for AFQMC. In general, AFQMC needs to be converged in the number of bands included in the basis. CoQuí allows us to select a subset of bands. One possible strategy is therefore to compute a relatively large number of bands here and let CoQuí write a subset of them. This avoids re-running the one-shot DFT calculation at the cost of saving more data.

Run the one-shot QE calculation.

3.5.3. Step 3: QE Post-Processing Utilities#

CoQuí reads some of the details of the pseudopotential from QE. We need to dump the relevant data to a file using the pw2coqui.x QE post-processing utility. As described above, you will need to install this utility into your QE build using the instructions found here. The input file files/qe/pw2coqui.in is

&input_pw2coqui
  prefix = "pwscf"
  outdir = "OUT"
/

!$QE_BIN/pw2coqui.x < ../files/qe/pw2coqui.in
Note:

Unlike many of the QE post-processing tools, the pw2coqui.x converter does not support MPI. Be sure to run the converter in serial as shown above!

If everything worked, the OUT directory generated by QE should now contain pwscf.coqui.h5 and pwscf.save.

!ls OUT

We’re ready to move on to CoQuí.

3.6. Writing the Second-Quantized Hamiltonian and Trial Wavefunction#

CoQuí is able to directly generate a Hamiltonian HDF5 file for SAFIRE using the data output by QE. Additionally, it can write a trial wavefunction based on the DFT solution from QE. These steps can be performed either separately or in a single input file. We will use the former approach and generate each separately for pedagogical reasons. In general, it is recommended to use a single CoQuí input file.

3.6.1. Writing the Hamiltonian#

CoQuí is controlled via a TOML-based input file. A sample CoQuí input file demonstrating how to generate a Hamiltonian is provided in files/coqui/hamil.toml.

[mean_field.qe]
name = "mf"
prefix = "pwscf"
outdir = "OUT"
nbnd = 20

[interaction.cholesky]
name        = "eri"
mean_field  = "mf"
output      = "hamil.h5"
write_type  = "single"
tol         = 1e-4  # you may need to converge this value!
ecut        = 50

[hamiltonian]
mean_field  = "mf"
interaction = "eri"
output      = "hamil.h5"

Here, we are using the Cholesky form of interaction (see Periodic Cholesky).

The key details to note are:

  1. In [mean_field.qe], we need to set the outdir to the directory where both the QE pwscf.xml file is saved, and where [prefix].coqui.h5 is.

  2. Also in [mean_field.qe], we can set the number of bands to use with nbnd. Of course, we can only use as many bands as we output in the one-shot DFT calculation previously.

  3. In the interaction input block, we are using the cholesky decomposed form for the interaction and have set a tolerance of tol = 1e-4. We have set the output to a file called hamil.h5 to tell CoQuí to save the interaction there. In general, one must converge the AFQMC energy in this parameter!

  4. The hamiltonian block is used to write the one-body part of the Hamiltonian to HDF5. We need to set this to the same file as the interaction.

Now, run CoQuí.

!$COQUI_EXEC ../files/coqui/hamil.toml

The HDF5 file, hamil.h5, that CoQuí just generated can be directly read in SAFIRE to get the Hamiltonian.

3.6.2. More Information#

For larger supercells, it is highly recommended that you use the tensor hypercontraction (THC) form of the interaction instead (see Tensor Hypercontraction). CoQuí can also generate these integrals by using an input block such as the following.

# Constructing THC-ERI by specifying the accuracy of the pivoted Cholesky
[interaction.thc]
name            = "eri"
mean_field      = "mf"
thresh          = 1e-6            
ecut            = 60
save            = "hamil.h5"
storage         = "incore"
Important:

SAFIRE currently only supports Γ-point THC.

3.6.3. Writing the Trial Wavefunction#

Finally, we can save a single Slater determinant wavefunction to HDF5 using a wavefunction block. The Slater determinant is constructed by occupying the Kohn-Sham orbitals with the largest occupancy. The sample input file files/coqui/wfn.toml is as follows:

[mean_field.qe]
name = "mf"
prefix = "pwscf"
outdir = "OUT"
nbnd = 20

[wavefunction.mf]
mean_field  = "mf"
output      = "wfn.h5"

The key points are that mean_field parameter in the [wavefunction.mf] must point to the name of the [mean_field.qe] block. You can use any *.h5 file name for the output parameter. This includes the HDF5 file containing the Hamiltonian if desired.

Now, run CoQuí on this input file.

!$COQUI_EXEC ../files/coqui/wfn.toml

3.7. Your Turn: Run SAFIRE#

You now have all the ingredients for an AFQMC calculation. Next, we’ll run SAFIRE using the Hamiltonian and trial wavefunction that we wrote using CoQuí. To learn more about the JSON job file, see Understanding the JSON Job File.

Your steps:

  1. make a JSON job file for SAFIRE to run using the Hamiltonian in hamil.h5 and the trial wavefunction in wfn.h5, both in the data directory.

  2. Run SAFIRE using that job file

  3. use safiretools to obtain the AFQMC energy

Hint

This is the same calculation as in Hello SAFIRE. Your energy should match the result there, Energy = -0.7299 ± 0.0017, to within stochastic uncertainty.
